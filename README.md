# CELESTIAL

登録なしで使う、ブラウザ内計算の天球ホロスコープ。日本語の操作画面、天球・2D円形図の連続切り替え、黄経による11種のアスペクト・6種の複合パターン・8種の追加天体、1800〜2200年の日時入力・現在時刻・時間スライダー・双方向の自動再生を備えます。

## 開発と公開

- `npm ci` / `npm run dev`
- `npm test` / `npx tsc --noEmit` / `npm run build`
- 公開物は `dist/client` のみ。`.openai/hosting.json` の同じSitesプロジェクトを使用してください。
- スキャフォールドのRSC静的生成がWindowsの共有ドライブで500を返したため、検証済みのReact画面をViteのクライアント専用ビルドに移行しています。サーバーレンダリング・API・DBは使用しません。

## プライバシー

日時・座標・UTC差は端末内で処理します。保存は初期状態で無効で、有効時のみlocalStorageの `celestial.observatory.v1` を使用します。無効化するとこのキーのみ削除します。外部データAPI、解析、広告、外部フォント、Cookie、アプリ用アカウントはありません。配信事業者による通常の接続情報の処理は別です。

ビルド後にCSP、Referrer-Policy、Permissions-Policyなどを生成します。スクリプトは同一オリジンのみ。インラインスクリプトがあれば個別ハッシュを使います。スタイル属性は描画・UIのため許可します。公開前のnpm auditで既知の脆弱性を確認してください。

## 計算

Astronomy Engine 2.1.19、地球中心、トロピカル黄道。天体は太陽・月・水星・金星・火星・木星・土星・天王星・海王星・冥王星。黄緯を含む方向を天球に配置し、2Dでは黄緯を0に投影します。距離と天体サイズ、背景の星は実寸表示ではありません。

アスペクトは黄経差により主要5種とマイナー6種（30/45/72/135/144/150度）を判定し、オーブは種類ごとに0〜10度。初期値は主要6度、マイナー2度。重なるオーブでは角度差が最小の種類を選択します。グランドトライン、Tスクエア、ヨッド、グランドクロス、カイト、ミスティックレクタングルは構成する全辺が種類別オーブを満たす場合のみ検出します。複合判定は通常ラインの種類別表示設定と独立し、構成線を金色表示します。全アスペクトラインのスイッチは両方を隠します。天球上の角距離を別に表示します。地平線とASC/MCは入力地点に対応。ハウスはイコールかホールサインの黄道上の境界です。出生データフォームでは都市のIANAタイムゾーンをブラウザのIntlで処理し、夏時間の存在しない時刻・重複する時刻を区別します。適用時にUTC差を確定し、時間再生中はその固定値を使います。歴史的な記録との差がある場合はUTC差を直接指定できます。

## 検証範囲

Nodeのテストで天体計算、日時境界、赤道・地平線の座標変換、アスペクト、3D/2D変形を検証。JSDOMで実際のReact状態を使った日時・再生・選択・保存・削除・WebMCPを検証。Three.jsシーンはGPU描画だけをテスト用に置き換え、実際のシーングラフ、アニメーション、リソース解放を検証します。これらは実GPUの画質や性能の検証ではありません。

WebMCPが利用できる環境では `set_observation_time` を提供します。対応ブラウザでの実機検証は別途必要です。対応しないブラウザでは機能を追加せず、通常の操作を利用できます。

## 追加天体と都市データ

追加天体はセレス、パラス、ジュノー、ベスタ、キロン、フォルス、エロス、プシュケ。NASA/JPL Horizonsから1799-12-01〜2201-02-01の地心ICRF赤道ベクトル（LT+S、UT、AU/day）を8日間隔で取得し、Float32で同梱します。3次Hermite補間の後、Astronomy Engineで日付の黄道座標へ変換します。240件の独立したJPL参照時刻との角度差は検証点で最大0.741秒角。これは全期間の誤差保証や元軌道の不確かさの評価ではありません。

初回の追加天体選択時のみ固定ファイル /ephemeris/asteroids.bin（約3.5MB）を同一サイトから取得します。出生フォーム初回は /data/cities.json（約6.2MB、34,135都市）を取得します。どちらも日時・座標・検索語をURLやbodyに含めません。検索と計算は端末内で実行し、再取得は不要です。任意の全小惑星や人口の少ない全地名を網羅するものではありません。未収録地点は座標指定に対応します。

都市データはGeoNames cities15000（CC BY 4.0）から項目・別名を抽出して加工。画面と同梱NOTICEで帰属を表示します。データ更新は scripts/build-asteroids.mjs、scripts/verify-asteroids.mjs、scripts/build-cities.mjs。都市ビルドは outputs/geonames/cities15000.txt を事前にGeoNames公開ZIPから展開します。JPL取得は逐次実行します。

## 観測者視点・感受点・現在地

3Dは観測地点の東・天頂・北に合わせた水平座標の向きに配置し、初期カメラと「地平線を水平に」は地平線が画面上でも水平になる位置を使います。2Dは従来どおり黄経投影でASCを左に配置し、通常の3D/2D切り替えでは座標系とカメラの向きを補間します。地上視点は天球中心に置いた透視カメラで東西南北やASC方向を見渡し、「地平線下も表示」（初期ON）で地面を透かして下側まで表示できます。OFFの場合のみ、地平線下の天体・ラベル・線をクリップします。海抜0mのObserverVectorで天体方向の地表視差を補正し、大気差・地形は含みません。表とアスペクト計算は地球中心のままです。

月のヘッド／テイルはGeoMoonStateの位置・速度から得た接触軌道面と日付の真黄道面の交点です（真交点、平均交点ではありません）。バーテックスは卯酉線と黄道の西側交点です。交点が定義できない場合は表示しません。3感受点は個別に表示／非表示を選べます。「感受点をアスペクトに含める」（初期ON）をOFFにすると、表示は残したまま通常・複合アスペクトの両方から除外します。ヘッドとテイル同士の組み合わせは、ONでも通常・複合判定から常に除外します。通り道は月軌道面、卯酉線に加え、黄経の時間変化を線で表示できます。ヘッド／テイルは前後360日を10日刻み、バーテックスは前後12時間を15分刻みで標本化します。

GPSボタンだけがgetCurrentPositionを呼び、初期表示時や再生中の自動追跡は行いません。ブラウザの許可が必要です。機器によってGPS・Wi-Fiなどの測位を使用します。取得座標は端末内で観測地点に適用し、日時は変更しません。拒否・未対応・タイムアウト・範囲外を扱い、遅延した結果は無視します。座標保存は既存のlocalStorage設定に従います。Permissions-Policyはgeolocation=(self)に限定します。アプリのサーバーへ座標を送信しませんが、端末・ブラウザ提供元の位置情報サービスはその規約に従います。

検証は水平面の画面投影、両半球のASC高度、独立した月交点イベント、バーテックスの方位、地表視差、地上カメラ、GPSの許可・拒否・時間切れを含みます。実GPUの描画や実機GPS測位は自動テストの対象外です。

## 2Dハウスと再生補間

2Dでは12本のハウス境界と1〜12の番号を初期表示します。「ハウス線」で切り替え可能で、3Dのハウス表示設定とは独立しています。方式は既存のイコール／ホールサインです。

再生中は既存の約10Hzの天体計算を維持し、到着した計算結果の間を描画フレームごとに補間します。天体・月軌道・移動軌跡を同じ補間時刻に揃え、ASC・MC・地平線・ハウスの基準はその時刻の軽いフレーム計算で更新します。高速再生で月などが1周以上進む場合は日速度から周回数を推定し、逆回転の見かけを避けます。計算更新が停止した場合に外挿して進み続けることはありません。

描画には通常約0.1秒の追従遅れがあります。補間窓は50〜200msですが、実際の遅れは処理負荷・計算結果の到着間隔にも依存します。画面の数値は最新計算値で、停止時に図形もその計算日時へ揃えます。「滑らかな再生（補間）」をOFFにするか動きを控える設定では補間を無効にします。高速再生中の補間図形は正確な時刻ごとの天文再計算ではなく近似表示です。

実装環境で、13天体・感受点と通り道を含む補間処理のCPU計測は約0.062ms/フレームでした（Nodeによる局所測定、実ブラウザ/GPUのFPS保証ではありません）。描画のテストでは計算更新間の各フレームでも天体が連続して動くこと、2Dハウスの初期表示・非表示を確認しています。
