# CELESTIAL

CELESTIALは、日時と地点を指定して天体の配置を確認できるWebアプリです。天体計算と都市検索はブラウザ内で行い、利用登録は不要です。

- 日本語・英語の操作画面
- 3D天球、2D円形図、地上視点、太陽系儀
- ライト、ダーク、システム設定に従う、現地の空の4テーマ
- 黄経による11種のアスペクト・6種の複合パターン・8種の追加天体
- 1800〜2200年の日時入力、現在時刻同期、時間スライダー、双方向の自動再生
- 7方式のハウス、月の真交点、バーテックス、真位置・平均位置を選べるリリス
- 日時・地点と表示設定を別々に保存する機能（初期状態ではOFF）

## 開発と公開

- コマンド
  - `npm ci` / `npm run dev`
  - `npm test` / `npx tsc --noEmit` / `npm run build`
- 公開物は `dist/client` のみです。`.openai/hosting.json` の同一Sitesプロジェクトを使用してください。
- Viteでクライアント専用の静的ファイルをビルドします。アプリの計算処理にサーバーレンダリング、API、データベースは使用しません。

## ライセンス・クレジットの表示

サイトの権利表記は `/credits.html` にまとめています。制作情報、MITライセンス全文、データの出典・加工内容、同梱フォントとライブラリの著作権表示をHTMLで表示します。`npm run dev` と `npm run build` の前処理で、`LICENSE` と実際にインストールした依存パッケージのライセンスから生成します。テキスト形式のライセンスと権利表記も配布物に含めます。クレジットページの配色は端末のライト／ダーク設定に従い、観測画面で手動指定したテーマとは連動しません。

## プライバシー

日時・座標・UTC差の計算処理はすべて端末内で完結します。

「このブラウザに日時・地点を保存」と「このブラウザに表示設定を保存」は独立した設定で、初期状態ではどちらもOFFです。有効にした項目だけをlocalStorageに保存します。

| 保存する項目 | 保存先 | 内容 |
| --- | --- | --- |
| 日時・地点 | `celestial.observatory.v1` | 観察日時、緯度経度、UTC差 |
| 表示設定 | `celestial.preferences.v1` | 言語、テーマ、再生条件、ハウス、天体・感受点・アスペクトの表示、種類別オーブ、リリスの種類など |

保存をOFFにすると、対応する保存先だけを削除します。共用端末では保存をOFFにしてください。

アプリには広告、アクセス解析、外部配信フォント、Cookieを使う保存処理を組み込んでいません。追加天体と都市検索に必要なデータは、同じサイトの静的ファイルから取得します。ページ配信や位置情報サービスを提供する事業者による通信・ログ処理には、それぞれの提供元の方針が適用されます。

- **セキュリティ方針**: ビルド時にCSP、Referrer-Policy、Permissions-Policyなどのセキュリティヘッダーを生成します。スクリプト実行は同一オリジンに限定し、インラインスクリプトがある場合は個別ハッシュで照合します。スタイル属性は動的描画とUI制御のために許可しています。本番公開前には `npm audit` を実行し、既知の脆弱性を確認してください。

## 計算

### 座標系と天体配置

天体位置の計算にはAstronomy Engine 2.1.19を採用し、地球中心・トロピカル黄道で算出します。基本天体は太陽・月・水星・金星・火星・木星・土星・天王星・海王星・冥王星の10天体です。黄緯を含む方向ベクトルを3D天球上に配置し、2D表示では黄緯を0として円周上に投影します。距離と天体サイズは視認性を優先した模式表現であり、実寸比率ではありません。背景の恒星は実測方向に基づいて配置します。

### アスペクト判定

アスペクトは黄経差をもとに判定します。

- **対応アスペクト**: メジャー5種、マイナー6種（30度、45度、72度、135度、144度、150度）
- **オーブ（許容度）**: 種類ごとに0〜10度の範囲で調整可能（初期値: メジャー6度、マイナー2度）
- **重複時の解決**: 複数のアスペクト条件が重なる角度では、角度差が最小となる種類を1つ選択
- **複合パターン**: グランドトライン、Tスクエア、ヨッド、グランドクロス、カイト、ミスティックレクタングルの6種を検出。構成する全辺が種類別オーブを満たす場合に限り検出し、金色で描画
- **表示切り替え**: 複合パターンの検出・金色表示は通常のアスペクトライン表示設定から独立して機能。全アスペクトラインの主スイッチをOFFにすると両方を非表示化。天球上の大円に沿った角距離は別途表示可能

### 基準点とタイムゾーン

地平線、ASC、MC、ハウス境界（カスプ）は、入力日時と地点から算出します。緯度の入力範囲は−89〜89°です。ハウスは7方式から選べ、イコール（ASC起点）が初期値です。各方式の定義と計算できない条件は「ハウス方式」に記載しています。

出生データ入力フォームでは、指定都市のIANAタイムゾーンをブラウザの `Intl` APIで判定し、夏時間の切り替えに伴う「存在しない時刻」や「重複する時刻」を区別します。確定したUTC差はシミュレーション再生中も固定値として保持します。歴史的改定などによりIANA値と記録に乖離がある場合は、UTC差を手動で直接指定できます。

## 検証範囲

- **Node環境**: 天体位置計算、日時の境界値処理、赤道・地平座標変換、アスペクト判定、3D/2D間の補間変形を自動テストで検証
- **JSDOM環境**: Reactの内部状態を用いた日時変更・再生制御・天体選択・設定の保存と削除・WebMCP連携を検証
- **Three.js環境**: GPUレンダリング部のみをモックに置き換え、シーングラフの構築、アニメーション更新、リソース解放処理をテスト

これらはアルゴリズムと状態遷移の検証であり、実GPUでの描画品質や実行性能を保証するものではありません。

WebMCPに対応した環境では、外部ツール連携用の `set_observation_time` を公開します。実機での動作確認は対応ブラウザで個別に行ってください。未対応のブラウザではWebMCP機能のみを無効化し、通常のUI操作はそのまま利用できます。

## 追加天体と都市データ

### 追加天体（小惑星・準惑星）

追加天体として、セレス、パラス、ジュノー、ベスタ、キロン、フォルス、エロス、プシュケの8天体を扱います。

- **エフェメリスデータ**: NASA/JPL Horizonsシステムから1799年12月1日〜2201年2月1日の期間における地心ICRF赤道ベクトル（光行差・重力たわみ補正済みLT+S、UT基準、単位AUおよびAU/day）を8日間隔で取得し、Float32形式のバイナリデータとして同梱
- **座標変換**: 3次Hermiteスプライン補間を行った後、Astronomy Engineを用いて計算日時の真黄道座標へ変換
- **精度照合**: 240件の独立したJPL参照データと照合した結果、検証点における角度差は最大0.741秒角（特定標本での検証結果であり、全期間にわたる誤差上限の保証や元軌道データの不確かさ評価ではありません）

### データ配信と都市検索

初回に追加天体を表示する際、同一オリジンから静的ファイル `/ephemeris/asteroids.bin`（約3.5MB）を取得します。同様に出生フォームの初回利用時に `/data/cities.json`（約6.2MB、34,135都市）を取得します。

- いずれの取得リクエストでも、日時・座標・検索キーワードをURLパラメータやリクエスト本文に含めません。
- 検索処理と軌道計算はすべて端末内で実行するため、データの再取得は不要です。
- 本データは既知の全小惑星や小規模な全集落を網羅するものではありません。一覧に未収録の地点は緯度経度の直接入力で対応します。

都市データはGeoNames cities15000（CC BY 4.0ライセンス）から主要項目と別名を抽出・加工したものです。画面上および同梱の [NOTICE.txt](public/data/NOTICE.txt) にクレジットを記載しています。データ更新用のスクリプトとして `scripts/build-asteroids.mjs`、`scripts/verify-asteroids.mjs`、`scripts/build-cities.mjs` を用意しています。都市データのビルドを実行する場合は、GeoNames公開ZIPから `outputs/geonames/cities15000.txt` を事前に展開してください。JPLからのエフェメリス取得スクリプトは、API負荷を避けるため逐次リクエストで実行します。

## 太陽系儀と天体の外観

太陽系儀は、太陽を中心に水星から冥王星までの惑星と月を表示します。天体位置はAstronomy Engineの太陽中心ベクトルから求め、月は地球の周囲に配置します。惑星間の距離は対数圧縮し、天体の大きさと地球から月までの距離は拡大しています。画面上の距離と大きさは実寸比率ではありません。

軌道線は、指定日時の位置・速度と重力定数から求めた接触軌道です。その瞬間の運動状態を二体問題の楕円で表しており、将来の実際の経路を予測する線ではありません。月の軌道線は地球中心の状態から求めます。

太陽系儀では、Astronomy Engineの自転軸と固定の自転周期を使って天体を回転させます。自転角は2000年1月1日12時UTCを基準に計算し、金星と天王星には逆方向の周期を使います。実際の表面模様の向きとの一致は保証しません。天球側の惑星マーカーは、この自転計算を使用していません。

天体の表面模様は描画用のイラストです。地球の陸地にはNatural Earthのデータを加工したマスクを使い、他の惑星の表面と雲模様は手続き的に生成します。土星と天王星の環も模式表示です。天球の陰影には視点に合わせた照明を使い、月相や日食・月食の再現を目的としていません。

## 観測者視点・感受点・現在地

### 座標系とカメラ視点

3D天球は、観測地点の地平線と天頂を基準にした局所水平座標系で配置します。初期カメラ位置および「地平線を水平に」ボタンでは、画面上で地平線が水平に保たれる視点位置を設定します。2D表示では従来のホロスコープと同様に黄経を円周へ投影し、ASC（東の地平線と黄道の交点）を左側に配置します。3Dと2Dの切り替え時には、座標系とカメラの姿勢を連続的に補間します。

地上視点モードでは、天球の中心に透視投影カメラを配置して東西南北やASC方向を見渡せます。「地平線下も表示」（初期設定ON）を有効にすると地面を透過して全天を表示し、OFFに設定した場合は地平線下の天体・ラベル・境界線をクリッピングして非表示にします。海抜0m基準の観測者位置ベクトルを用いて天体方向の地表視差を補正します。大気差および地形による遮蔽は計算に含めません。天体一覧表の数値およびアスペクト判定は、占星術の慣例に従い地球中心座標系を維持します。

### 感受点と軌跡

- **月のノード（ヘッド／テイル）**: Astronomy Engineの `GeoMoonState` から取得した位置・速度ベクトルから接触軌道面を求め、計算日時の真黄道面との交点として算出（真交点方式。平均交点ではありません）。
- **バーテックス**: 卯酉線（東西を通る垂直圏）と黄道面の西側交点として算出。幾何学的に交点が定義できない高緯度条件では表示を省略。
- **アスペクト設定**: ヘッドとテイルは一組として、バーテックスと選択中のリリスはそれぞれ表示を切り替えます。リリスは真位置と平均位置から選べます。「感受点をアスペクトに含める」（初期設定ON）をOFFにすると、画面表示は維持したままアスペクト判定対象から除外。ヘッドとテイルの組み合わせは常時除外。
- **軌跡の標本化**: 月軌道面と卯酉線の補助線に加え、ヘッド・テイル・バーテックスの黄経変化を軌跡として表示できます。標本化間隔はヘッド／テイルが前後360日間を10日刻み、バーテックスが前後12時間を15分刻み。

### 現在地測位（GPS）

GPSボタンを押した時のみブラウザの `navigator.geolocation.getCurrentPosition` を呼び出します。初期表示時やアニメーション再生中に位置情報を自動追跡することはありません。

- **測位処理**: 端末のGPSやWi-Fi測位を利用。取得座標は端末内でのみ観測地点として反映し、日時は変更しません。
- **例外対応**: 権限拒否、未対応ブラウザ、タイムアウト、無効な座標値を判定してエラー処理し、遅延到着した結果は破棄。
- **権限とプライバシー**: 座標保存はlocalStorage設定に連動。Permissions-Policyヘッダーは `geolocation=(self)` に限定。アプリ独自サーバーへの送信は行いません（端末OS・ブラウザ提供元の規約は各方針に従います）。

自動テストでは、水平面の画面投影変換、南北両半球におけるASC高度、月交点イベントの通過時刻、バーテックスの方位角、地表視差補正、地上視点カメラの挙動、GPS APIの各種応答処理を検証しています。実GPU上での描画外観や実機でのGPS測位精度は自動テストの検証対象外です。

## 2Dハウスと再生補間

### 2Dハウス表示

2D表示では、12本のハウス境界線と1〜12のハウス番号を初期状態で表示します。この表示は「ハウス線」設定で切り替え可能であり、3D側のハウス表示設定とは連動せず独立して保持されます。分割方式は3Dと共通で、対応する7方式から選べます。方式を計算できない条件では境界線と番号を非表示にします。

### 再生補間アルゴリズム

時間再生中、天体の精密軌道計算は約10Hzの周期で実行されます。描画フレームごとの滑らかな動きを実現するため、直近に到着した2つの計算結果の間を線形補間して天体位置を表示します。

- **フレーム更新**: 天体、月軌道面、移動軌跡を同一の補間時刻に揃え、ASC・MC・地平線・ハウスカスプは補間時刻をもとに軽量なフレーム計算で毎フレーム更新。
- **周回数補正**: 高速再生時に公転速度の速い天体が1フレームで1周以上進む場合、前後の日速度から周回数を推定して適切な回転方向を維持し、見かけ上の逆回転を防止。
- **外挿防止**: 計算の到着が途絶えた場合に外挿して進み続けることはなく、最終計算時刻で停止。

### 遅延と負荷制御

補間表示の構造上、描画には通常約0.1秒の追従遅れが生じます。補間バッファの長さは50〜200msですが、実際の遅延量は端末のCPU負荷や計算結果の配信間隔によって変動します。画面上に表示されるテキスト数値は常に最新の確定計算値であり、再生を停止した瞬間に図形側の描画もその確定計算値の日時へ同期します。

描画遅れを許容しない場合や端末の負荷を抑えたい場合は、「滑らかな再生（補間）」をOFFにするか、OSの「視覚効果を減らす」設定を有効にすることで補間処理を完全に停止できます。なお、高速再生中の補間描画はフレームごとの厳密な天文再計算ではなく幾何学的な補間表示です。

描画テストでは、計算結果が更新される間も天体が移動することと、2Dハウスの表示切り替えを確認しています。これらのテストは実GPUでの表示品質やフレームレートを保証するものではありません。

## リリス

リリスは表示をONにした状態で開始し、「真位置」（初期値）と「平均位置」を切り替えられます。種類を変えても、表示・非表示とアスペクトへの参加設定は引き継ぎます。

### 真位置（True Lilith）

True Lilithは、月の接触軌道における遠地点（アポジー）を指します。平均遠地点（Mean Lilith）、補間遠地点、小惑星1181番Lilithとは定義が異なります。

#### 計算手順

1. Astronomy Engineの `GeoMoonState`（地心EQJ座標系、位置AU・速度AU/day）と地球・月の重力定数（GM）から軌道の離心率ベクトルを算出
2. 離心率ベクトルの反対方向を計算日時の真黄道座標系へ回転させて遠地点の方向を決定（黄緯成分も保持）
3. 日速度は前後1時間の中心差分法で算出

占星術上の感受点として扱い、通常アスペクト・複合パターンの共通スイッチ設定に従います。地表視差補正は適用しません。計算のための追加ネットワーク通信は発生しません。本実装はAstronomy Engineの月近似暦に基づいているため、Swiss Ephemerisとの完全な一致や秒角レベルの高精度を保証するものではありません。なお、軌跡表示の対象はヘッド、テイル、バーテックスの3点であり、True Lilithの軌跡表示は行いません。

#### 定義と検証

- **定義の参照基準**: [Swiss Ephemeris §2.2.3](https://www.astro.com/swisseph/swisseph.htm)。接触軌道とは、その瞬間における位置と速度ベクトルから決定される二体問題の仮想的な楕円軌道であり、将来の実際の日時における月の最遠到達点を直接予測するものではありません。
- **精度検証**: 公式Swiss Ephemerisの `swetest64.exe` および高精度月暦 `semo_18.se1` を用いて算出した `SE_OSCU_APOG` の基準値199点（1801年から900日刻みで162点、2026年から10日刻みで37点）を [tests/lilith-fixtures.json](tests/lilith-fixtures.json) に記録し照合テストを実施。
- **検証結果**: 検証用標本における誤差は黄経差で最大約0.16050°、黄緯差で最大約0.01297°、日速度差で最大約0.05296°/日。この測定差は用意した標本における比較結果であり、全期間にわたる誤差の上限を保証するものではありません。なお、Swiss Ephemerisの公式バイナリおよび暦ファイルは開発時の精度検証にのみ使用しており、Webサイトの配布物には含めません。

### 平均位置（Mean Lilith）

Mean Lilithは月の平均軌道の遠地点です。Meeus『Astronomical Algorithms』第2版、第47章の平均軌道要素を使い、傾斜した月軌道上の遠地点方向を黄道座標に変換します。章動を加え、黄緯も保持します。日速度は前後12時間の差から求めます。

真位置と同じ199日時について、Swiss Ephemerisの参照値と照合しています。現行実装と参照標本の差は、黄経で最大約0.00063°、黄緯で最大約0.000063°、日速度で最大約0.000021°/日です。テストの許容差は黄経0.001°、黄緯0.0001°、日速度0.00003°/日です。参照標本は [mean-lilith-fixtures.json](tests/mean-lilith-fixtures.json) に収録しています。この許容差は標本の照合基準であり、全日時の誤差上限ではありません。

## 今の星を眺める・実座標の恒星

### 「今の星を眺める」全画面モード

選択中の観測地点を保持したまま現在時刻へ1秒ごとに同期する全画面表示モードです。

- **カメラの挙動**: 視点カメラが約4分で天球を1周。ドラッグ操作や拡大縮小を行った場合は回転を一時停止し、操作終了から5秒後に自動回転を再開（手動停止も可能）。OSまたはアプリの「視覚効果を減らす」設定が有効な場合は初期状態で自動回転を停止。
- **UI表示**: 現在時刻、テーマ選択、回転制御、終了ボタンを表示します。天球内の文字ラベルは非表示にします。
- **状態管理**: 戻る操作またはEscキーで元の観察日時とカメラ位置へ戻り、通常の時間再生は停止します。モード内で変更したテーマは終了後も引き継ぎます。ブラウザの別タブへ切り替えた際は更新タイマーを停止し、タブ復帰時に実時刻へ再同期。保存済みの出生データ設定を上書きすることはなく、GPS測位やネットワーク通信を自動で開始することもありません。

### 恒星データ

ESA (1997), The Hipparcos and Tycho Catalogues, ESA SP-1200 / CDS VizieR I/239/hip_main からV等級1.5以下の明るい恒星22星を抽出して収録しています（画面上で分離表示できないケンタウルス座アルファ星Bは除外）。

- **座標計算**: ICRS座標系・元期J1991.25における赤経・赤緯および固有運動パラメータを用い、計算日時の真黄道座標へ変換して天球視点および地上視点の観測者座標系に配置。固有運動、歳差、章動を反映。
- **除外事項**: 年周光行差、年周視差、視線速度に伴う遠近効果、大気差、大気減光は計算に含めません。
- **表示仕様**: 描画サイズは等級値をもとに視認性を考慮して調整した模式表現。恒星座標の再計算はシミュレーション時刻の1分ごとに行い、地平座標系への姿勢同期は天球と同時に更新。2Dホロスコープ表示では恒星を表示しません。
- **通信**: データはすべてクライアントコード内に組み込まれており、追加通信は発生しません。

出典情報: [VizieR I/239](https://cdsarc.cds.unistra.fr/viz-bin/cat/I/239) 、VizieR service DOI: 10.26093/cds/vizier。自動テストでは、星表元期からの固有運動伝播、真黄道座標および局所地平座標への変換精度、「今の星を眺める」モードにおける1秒ごとの時刻同期、設定値の非破壊保持、終了時のカメラ姿勢復帰を検証しています。実GPU上での外観確認は自動テストに含まれません。

## 表示テーマ

画面上部ヘッダーおよび「今の星を眺める」内のテーマ選択UIから、「ライト」「ダーク」（初期値）「システム設定に従う」「現地の空」の4つの表示テーマを切り替えられます。テーマを切り替えても視点カメラ、観察日時、観測地点の設定は変化しません。「システム設定に従う」は端末のライト／ダーク設定に追従し、ページを開いたまま設定を変更しても反映します。テーマの選択状態はサーバーへ送信せず、「表示設定を保存」が有効な場合のみlocalStorageに保存します。ライト配色は背景色だけでなく、設定ダイアログのUI要素や天体記号の描画色にも連動して適用されます。

### 「現地の空」テーマ

選択された日時と地点における太陽の地表視差補正済み幾何高度をもとに、晴天時の昼間、薄明、夜間の背景色を近似表現します。

- **薄明の定義**: 米国海軍天文台（USNO）の定義に従い、太陽高度 −6度（市民薄明）、−12度（航海薄明）、−18度（天文薄明）を採用（定義参照: [USNO Rise, Set, and Twilight Definitions](https://aa.usno.navy.mil/faq/RST_defs) ）。
- **モデルの範囲**: 背景色および恒星の減光処理は視覚的な演出を目的とした近似モデルであり、物理的な大気散乱や測光モデルに基づくものではありません。天候、雲量、月明かり、人工光害、大気差、大気組成の変化は考慮しません。
- **視認性と連動**: チャートの判読性を維持するため、天体マーカーやアスペクトラインは昼間でも視認可能な輝度で表示。地上視点モードのグラデーションは地平線の向きおよび太陽方位に連動し、「地平線下も表示」の透過設定を維持。2D表示では太陽高度に応じた明暗の単色盤面となります。
- **描画負荷**: 既存の天体計算結果を再利用し、ポリゴン数を抑えた単一球体メッシュと軽量なカスタムシェーダーで描画。外部APIや追加のポストプロセス描画パスは使用しません。

## ハウス方式

### 対応する7方式

プラシーダス、キャンパナス、コッホ、レギオモンタナス、ポーフィリー、イコール（ASC起点、初期値）、ホールサインから選べます。2Dおよび3Dの天球上に黄道面との交点であるカスプを描画し、ハウス番号（1〜12）は隣接するカスプ境界の中央位置に表示します。シミュレーション再生中は補間された時刻をもとに毎フレーム再計算します。3D天球上に描かれる線は黄道面上のカスプ位置を示す境界線であり、天球空間全体を分割する三次元の境界面ではありません。

- **プラシーダス方式**: 黄道上の各点が地平線から子午線へ移動する半日弧・半夜弧の三等分条件を二分法による数値計算で解いて決定。極圏（観測地点の緯度の絶対値が $90^\circ - \epsilon$ 以上となる地域。 $\epsilon$ は当日の黄道傾斜角）や、周極により解が収束しない条件下では、計算不可の理由を画面に明示してハウス境界線を非表示化（他方式への自動切替は行いません）。
- **キャンパナス方式**: 卯酉線の30度等分点と地平線の南北軸を含む平面群が黄道と交差する点として算出。極圏では幾何学的配置の逆転により、第10ハウスのカスプがMC（天頂方向の子午線交点）の正反対側に位置する場合があります。
- **イコール方式**: ASCを第1カスプ起点とし、黄道上を30度ずつ等分。
- **ホールサイン方式**: ASCが存在するサインの0度を第1カスプとし、サイン全体を1つのハウスとして割り当て。

ハウス定義の参照先: [Astrodienst House System Information](https://www.astro.com/cgi/h.cgi?f=gch&h=gch_h3&lang=e) および [Swiss Ephemeris Documentation 6.4](https://www.astro.com/swisseph/swisseph.htm) 。本機能は数理定義に基づき独立して実装した幾何計算であり、Swiss Ephemerisのソースコードやバイナリは一切含んでいません。外部の `swetest 2.10.03` を用いて、1900年〜2199年の範囲から南北両半球および高緯度地域を含む210件の条件を抽出して照合テストを実施しました。その結果、算出された黄経差は最大0.001042度であり、許容誤差基準0.002度を満たしています。なお、この結果は全日時・全地点における誤差の上限を理論的に保証するものではありません。

### コッホ・レギオモンタナス・ポーフィリーの定義

- **コッホ方式**: MCが黄道と交差する点の半日弧を基準とし、時角をずらした仮想地平線と黄道の交点として算出。極圏では定義不能となるため選択不可とし、他方式への自動フォールバックは行いません。
- **レギオモンタナス方式**: 天の赤道の30度等分点と地平線の南北軸を含む各大円が黄道と交差する点として算出。
- **ポーフィリー方式**: 四分円（ASCとMC、MCとDSC、DSCとIC、ICとASCの間の黄道弧）をそれぞれ三等分して決定。極圏ではASCの位置を基準とし、四分円が反時計回りに順序正しく並ぶ側の子午線交点をMCとして採用。

3D天球上で表示できるスフィア補助線では、各方式の空間的定義を視覚化します。コッホ方式では過去および未来の地平線と子午線の作図線を表示します（これらの線は天球上で交差し、空間を排他的に分割する境界面ではありません）。レギオモンタナス方式では各大円を表示し、ポーフィリー方式では黄道上のカスプ位置から黄道極へ向かう黄経線を延長表示します。

定義の参照先: [Swiss Ephemeris House Systems](https://www.astro.com/swisseph/sweph_ht_e.htm) 。独立実装による算出値をSwiss Ephemeris `swetest 2.10.03` の出力（1900年〜2199年、南北両半球および極圏を含む154チャート）と比較検証したところ、カスプの黄経差は最大0.001002度でした。検証用参照データは [tests/house-additions-reference.json](tests/house-additions-reference.json) に収録しています。Swiss Ephemerisの実行コード自体は配布物に含みません。

## 表示の視認性調整

- **ハウス番号ラベル**: 画面上での表示高さを28〜32pxの範囲に保ち、不透明度を高く設定して重なり時の視認性を確保。
- **天球の裏側を暗くする（初期設定OFF）**: 表示設定の保存対象。有効にすると、3D天球を外側から俯瞰する視点において、奥側に位置する線・天体・記号の表示を距離に応じて減光（2Dおよび地上視点では無効）。影の計算や追加描画パスは使用せず、頂点処理の深度判定のみで制御。
- **フォント構成**:
  - 英数字: Google FontsのSource Code Pro（ウェイト300〜700）を同梱
  - 日本語: BIZ UDPGothicを採用
  - 12星座記号: テキスト表示指定（`U+FE0E`）を付与し、Noto Sans Symbolsの星座記号サブセットフォントを適用してOSによるカラー絵文字への自動置換を防止
  - 配信とライセンス: すべて自サーバーの同一オリジンから配信。フォント別のライセンス全文はクレジットページと [OFL.txt](public/fonts/OFL.txt)、[SourceCodePro-OFL.txt](public/fonts/SourceCodePro-OFL.txt)、[ZodiacSymbols-OFL.txt](public/fonts/ZodiacSymbols-OFL.txt) に収録しています。
