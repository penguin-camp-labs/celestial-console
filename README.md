# CELESTIAL

登録なしで使う、ブラウザ内計算の天球ホロスコープ。日本語の操作画面、天球・2D円形図の連続切り替え、黄経による11種のアスペクト・6種の複合パターン・8種の追加天体、1800〜2200年の日時入力・現在時刻・時間スライダー・双方向の自動再生を備えます。

## 開発と公開

- `npm ci` / `npm run dev`
- `npm test` / `npx tsc --noEmit` / `npm run build`
- 公開物は `dist/client` のみ。`.openai/hosting.json` の同じSitesプロジェクトを使用してください。
- スキャフォールドのRSC静的生成がWindowsの共有ドライブで500を返したため、検証済みのReact画面をViteのクライアント専用ビルドに移行しています。サーバーレンダリング・API・DBは使用しません。

## プライバシー

日時・座標・UTC差は端末内で処理します。保存は初期状態で無効で、有効時のみlocalStorageの `celestial.observatory.v1` を使用します。無効化するとこのキーのみ削除します。外部データAPI、解析、広告、外部フォント、Cookie、アプリ用アカウントはありません。配信事業者による通常の接続情報の処理は別です。

ビルド後にCSP、Referrer-Policy、Permissions-Policyなどを生成します。スクリプトは同一オリジンのみ。インラインスクリプトがあれば個別ハッシュを使います。スタイル属性は描画・UIのため許可します。公開前のnpm auditで既知の脆弱性を確認してください。

## 計算

Astronomy Engine 2.1.19、地球中心、トロピカル黄道。天体は太陽・月・水星・金星・火星・木星・土星・天王星・海王星・冥王星。黄緯を含む方向を天球に配置し、2Dでは黄緯を0に投影します。距離と天体サイズは実寸表示ではありません。背景の恒星は実測の方向を使用します。

アスペクトは黄経差により主要5種とマイナー6種（30/45/72/135/144/150度）を判定し、オーブは種類ごとに0〜10度。初期値は主要6度、マイナー2度。重なるオーブでは角度差が最小の種類を選択します。グランドトライン、Tスクエア、ヨッド、グランドクロス、カイト、ミスティックレクタングルは構成する全辺が種類別オーブを満たす場合のみ検出します。複合判定は通常ラインの種類別表示設定と独立し、構成線を金色表示します。全アスペクトラインのスイッチは両方を隠します。天球上の角距離を別に表示します。地平線とASC/MCは入力地点に対応。ハウスはイコールかホールサインの黄道上の境界です。出生データフォームでは都市のIANAタイムゾーンをブラウザのIntlで処理し、夏時間の存在しない時刻・重複する時刻を区別します。適用時にUTC差を確定し、時間再生中はその固定値を使います。歴史的な記録との差がある場合はUTC差を直接指定できます。

## 検証範囲

Nodeのテストで天体計算、日時境界、赤道・地平線の座標変換、アスペクト、3D/2D変形を検証。JSDOMで実際のReact状態を使った日時・再生・選択・保存・削除・WebMCPを検証。Three.jsシーンはGPU描画だけをテスト用に置き換え、実際のシーングラフ、アニメーション、リソース解放を検証します。これらは実GPUの画質や性能の検証ではありません。

WebMCPが利用できる環境では `set_observation_time` を提供します。対応ブラウザでの実機検証は別途必要です。対応しないブラウザでは機能を追加せず、通常の操作を利用できます。

## 追加天体と都市データ

追加天体はセレス、パラス、ジュノー、ベスタ、キロン、フォルス、エロス、プシュケ。NASA/JPL Horizonsから1799-12-01〜2201-02-01の地心ICRF赤道ベクトル（LT+S、UT、AU/day）を8日間隔で取得し、Float32で同梱します。3次Hermite補間の後、Astronomy Engineで日付の黄道座標へ変換します。240件の独立したJPL参照時刻との角度差は検証点で最大0.741秒角。これは全期間の誤差保証や元軌道の不確かさの評価ではありません。

初回の追加天体選択時のみ固定ファイル /ephemeris/asteroids.bin（約3.5MB）を同一サイトから取得します。出生フォーム初回は /data/cities.json（約6.2MB、34,135都市）を取得します。どちらも日時・座標・検索語をURLやbodyに含めません。検索と計算は端末内で実行し、再取得は不要です。任意の全小惑星や人口の少ない全地名を網羅するものではありません。未収録地点は座標指定に対応します。

都市データはGeoNames cities15000（CC BY 4.0）から項目・別名を抽出して加工。画面と同梱NOTICEで帰属を表示します。データ更新は scripts/build-asteroids.mjs、scripts/verify-asteroids.mjs、scripts/build-cities.mjs。都市ビルドは outputs/geonames/cities15000.txt を事前にGeoNames公開ZIPから展開します。JPL取得は逐次実行します。

## 観測者視点・感受点・現在地

3Dは観測地点の東・天頂・北に合わせた水平座標の向きに配置し、初期カメラと「地平線を水平に」は地平線が画面上でも水平になる位置を使います。2Dは従来どおり黄経投影でASCを左に配置し、通常の3D/2D切り替えでは座標系とカメラの向きを補間します。地上視点は天球中心に置いた透視カメラで東西南北やASC方向を見渡し、「地平線下も表示」（初期ON）で地面を透かして下側まで表示できます。OFFの場合のみ、地平線下の天体・ラベル・線をクリップします。海抜0mのObserverVectorで天体方向の地表視差を補正し、大気差・地形は含みません。表とアスペクト計算は地球中心のままです。

月のヘッド／テイルはGeoMoonStateの位置・速度から得た接触軌道面と日付の真黄道面の交点です（真交点、平均交点ではありません）。バーテックスは卯酉線と黄道の西側交点です。交点が定義できない場合は表示しません。4感受点（ヘッド・テイル・バーテックス・True Lilith）は個別に表示／非表示を選べます。「感受点をアスペクトに含める」（初期ON）をOFFにすると、表示は残したまま通常・複合アスペクトの両方から除外します。ヘッドとテイル同士の組み合わせは、ONでも通常・複合判定から常に除外します。通り道は月軌道面、卯酉線に加え、黄経の時間変化を線で表示できます。ヘッド／テイルは前後360日を10日刻み、バーテックスは前後12時間を15分刻みで標本化します。

GPSボタンだけがgetCurrentPositionを呼び、初期表示時や再生中の自動追跡は行いません。ブラウザの許可が必要です。機器によってGPS・Wi-Fiなどの測位を使用します。取得座標は端末内で観測地点に適用し、日時は変更しません。拒否・未対応・タイムアウト・範囲外を扱い、遅延した結果は無視します。座標保存は既存のlocalStorage設定に従います。Permissions-Policyはgeolocation=(self)に限定します。アプリのサーバーへ座標を送信しませんが、端末・ブラウザ提供元の位置情報サービスはその規約に従います。

検証は水平面の画面投影、両半球のASC高度、独立した月交点イベント、バーテックスの方位、地表視差、地上カメラ、GPSの許可・拒否・時間切れを含みます。実GPUの描画や実機GPS測位は自動テストの対象外です。

## 2Dハウスと再生補間

2Dでは12本のハウス境界と1〜12の番号を初期表示します。「ハウス線」で切り替え可能で、3Dのハウス表示設定とは独立しています。方式は既存のイコール／ホールサインです。

再生中は既存の約10Hzの天体計算を維持し、到着した計算結果の間を描画フレームごとに補間します。天体・月軌道・移動軌跡を同じ補間時刻に揃え、ASC・MC・地平線・ハウスの基準はその時刻の軽いフレーム計算で更新します。高速再生で月などが1周以上進む場合は日速度から周回数を推定し、逆回転の見かけを避けます。計算更新が停止した場合に外挿して進み続けることはありません。

描画には通常約0.1秒の追従遅れがあります。補間窓は50〜200msですが、実際の遅れは処理負荷・計算結果の到着間隔にも依存します。画面の数値は最新計算値で、停止時に図形もその計算日時へ揃えます。「滑らかな再生（補間）」をOFFにするか動きを控える設定では補間を無効にします。高速再生中の補間図形は正確な時刻ごとの天文再計算ではなく近似表示です。

実装環境で、13天体・感受点と通り道を含む補間処理のCPU計測は約0.062ms/フレームでした（Nodeによる局所測定、実ブラウザ/GPUのFPS保証ではありません）。描画のテストでは計算更新間の各フレームでも天体が連続して動くこと、2Dハウスの初期表示・非表示を確認しています。

## True Lilith

True Lilith（初期表示ON）は月の接触軌道の遠地点で、平均遠地点・補間遠地点・小惑星1181 Lilithとは異なります。Astronomy EngineのGeoMoonState（地心EQJ、AU・AU/day）と地球＋月のGMから離心率ベクトルを求め、その反対方向を日付の真黄道座標へ回転します。黄緯も保持し、日速度は前後1時間の中心差分。感受点として通常・複合アスペクトの共通トグルに従い、地表視差を適用しません。追加のネットワーク取得はありません。月の近似暦を使うためSwiss Ephemerisとの完全一致や秒角精度は保証しません。軌跡表示は既存のヘッド・テイル・バーテックスが対象です。

定義の参照: [Swiss Ephemeris §2.2.3](https://www.astro.com/swisseph/swisseph.htm)。接触軌道はその瞬間の位置・速度から定まる二体問題の楕円で、後日の実際の月の最遠点を予測するものではありません。

検証: 公式Swiss Ephemerisのswetest64.exeとsemo_18.se1でSE_OSCU_APOGを計算した199点（1801年から900日刻み162点、2026年から10日刻み37点）をtests/lilith-fixtures.jsonに記録。黄経差最大0.16051°、黄緯差最大0.01298°、日速度差最大0.05297°/日。これは標本での差で、全期間の精度保証ではありません。公式バイナリと月暦は検証時だけ使用し、サイト配布物には含めません。

## 今の星を眺める・実座標の恒星

「今の星を眺める」は選択中の地点を使い、現在時刻へ1秒ごとに同期する集中画面です。視点だけが約4分で1周し、ドラッグや拡大操作の後は5秒待って回転を再開します。回転は停止可能で、OSやアプリの控えめなアニメーション設定がONなら自動回転しません。時刻・回転・終了だけを表示し、天球内の文字を隠します。戻る/Escで元の日時・表示設定・カメラに戻り、通常の高速再生は停止します。別タブではタイマーを止め、復帰時に実時刻へ同期。保存済み出生日時を上書きせず、GPSや通信は自動開始しません。

恒星はESA (1997), The Hipparcos and Tycho Catalogues, ESA SP-1200 / CDS VizieR I/239/hip_mainからV等級1.5以下の22星を収録（画面で分離できないAlpha Centauri Bを除外）。ICRS・元期J1991.25の赤経赤緯と固有運動を使用し、日付の真黄道座標に変換して天球・地上視点の同じ観測者座標に配置します。固有運動・歳差・章動を反映。年周光行差、年周視差、視線速度による遠近効果、大気差、昼光・大気減光は含めません。星の大きさは等級をもとに見やすく調整した模式表現です。座標更新はシミュレーション時刻の1分単位、地平線への向きは天球と同時更新。2Dでは恒星を隠します。データはバンドル済みで追加通信はありません。

出典: https://cdsarc.cds.unistra.fr/viz-bin/cat/I/239 、VizieR service DOI: 10.26093/cds/vizier。星表の元期復元・固有運動・地平座標への変換、集中モードの1秒同期・保存保持・カメラ復帰を自動テストで検証。実GPUの外観確認は含みません。


## 表示テーマ

ヘッダーおよび「今の星を眺める」のテーマ選択で、ライト・ダーク（初期値）・現地の空を切り替えます。切り替えは視点や日時・地点を変えず、テーマ選択自体を保存・送信しません。ライト配色は設定ダイアログや天体記号にも適用します。

「現地の空」は選択日時と地点の太陽の地表視差を含む幾何高度から、晴天の昼・薄明・夜の背景を近似します。薄明の境界は太陽高度 −6° / −12° / −18°（USNO: https://aa.usno.navy.mil/faq/RST_defs）。色・恒星の減光は視覚表現で、測光モデルではありません。天候、月明かり、光害、大気差・大気組成は含みません。天体マーカーとアスペクトは読み取りのため昼も表示します。地上視点の空のグラデーションは地平線・太陽方位に対応し、地平線下の透過設定を維持します。2Dでは太陽高度に応じた明暗の盤面です。

既存の天体計算結果を再利用し、再生補間した日時でも太陽高度・背景色を更新します。背景は低分割の単一球と簡単なシェーダーで、外部APIや画像生成、追加の描画パスは使いません。GPU上の表示・速度は環境に依存します。


## ハウス方式

プラシーダス、キャンパナス、イコール（ASC起点・初期値）、ホールサインを画面上から選べます。2D/3Dに黄道上のカスプを描き、番号は各境界間の中央です。再生中は補間された日時で再計算します。3Dは境界の黄経であり空間の区画面ではありません。

プラシーダスは各黄道点自身の半日弧・半夜弧の三等分条件を二分法で解きます。極圏（緯度の絶対値が90°−当日の黄道傾斜角以上）や解が確定しない場合は理由を表示し、ハウス線を隠します。自動的な代替方式は使いません。キャンパナスは卯酉線の30°分割点と地平線の南北軸を含む平面を黄道と交差させます。極圏では幾何学的定義により順序が逆転し、第10カスプが通常のMCの反対側になる場合があります。

定義参考：https://www.astro.com/cgi/h.cgi?f=gch&h=gch_h3&lang=e と https://www.astro.com/swisseph/swisseph.htm （6.4）。独立した幾何計算で、Swiss Ephemerisのコード・実行ファイルは配布しません。外部swetest 2.10.03で1900〜2199年、南北半球、高緯度の210条件を照合。黄経差は最大0.001042°、許容値0.002°。全日時の誤差上限を保証するものではありません。

## 追加ハウス方式
コッホ・レギオモンタナス・ポーフィリーを追加し、全7方式を選択・保存できます。コッホはMC黄道点の半日弧から時刻をずらした地平線の交点、レギオモンタナスは天の赤道の30度分割点と地平線南北軸を含む大円、ポーフィリーは黄道四分円の三等分で求めます。極圏のポーフィリーはASCを維持し、四分円が順に並ぶ側の子午線交点を使います。
スフィア補助線では、コッホは過去・未来の地平線と子午線の作図線（線同士が交差し、空間を重なりなく分割する面ではありません）、レギオモンタナスは大円、ポーフィリーは黄経区分を黄道極まで延長して表示します。コッホは極圏で利用不可とし、代替方式へ自動変更しません。
定義: https://www.astro.com/swisseph/sweph_ht_e.htm 。独立実装をSwiss Ephemeris swetest 2.10.03の154チャート（1900〜2199年、南北両半球・極圏を含む）と比較し、カスプ差は最大0.001002度でした。参照値はtests/house-additions-reference.json。Swiss Ephemerisの実行コードは配布しません。
